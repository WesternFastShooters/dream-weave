# Public and backend capability map

This map is the canonical trace from a browser-visible capability to its contract, server owner, durable or asynchronous work, boundary, and tests. Browser composition delegates to these capabilities from [runtime architecture](overview.md), while item-specific use is indexed by the [canvas node catalog](../domain/canvas-node-catalog.md).

## Office topology

The Office viewer shell fetches an opaque bootstrap configuration instead of receiving its document URL or token from its embedding app parent. It then loads DocsAPI and reports only readiness/error and session ID back to the parent. Nginx on the Office origin routes `/internal/office-viewer-sessions/` to the server and DocsAPI/remaining Document Server paths to the shell. Local and Helm configurations allow ONLYOFFICE access to the private source proxy and customize embedded preview presentation. This design implements the [Office security boundary](../domain/security.md) and is operated through the [runbook](../operations/runbook.md).

## Change checklist

- Edit `.proto` rather than generated output, run `make -C apps/server api`, then `make -C apps/server verify`.
- A mutation change must keep TypeScript adaptation, Go transport/validation, PostgreSQL revision/receipt behavior, and tests aligned.
- An asset/Office change must preserve distinct browser and Document Server capability audiences, origin routing, and CIDR enforcement; run [testing guidance](../testing/quality.md) rather than fixture UI alone.
